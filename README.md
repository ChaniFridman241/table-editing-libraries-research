# בדיקת ספריות React לעריכה טבלאית

**זהו פרויקט מחקר.** הוא בודק את היכולות של ספריות שונות לעריכה טבלאית ב-React. המטרה היא לברר מה הספריות נותנות מוכן, ומה צריך לבנות לבד, בכל מה שקשור ל:

- עריכת נתונים בטבלה: הוספה, מחיקה, עדכון
- שמירה למסד נתונים, סינכרונית וא-סינכרונית
- ביטול פעולה אחרונה (Undo)
- עבודה של כמה משתמשות במקביל, וזיהוי התנגשויות
- דפדוף, ריענון ומעבר בין מסכים

כדי לבדוק את זה בפועל נבנתה מערכת דמו קטנה לניהול עובדים.

## הספריות שנבדקו בפרויקט

| ספרייה | תפקיד | מה היא נותנת מוכן | מה היא לא עושה |
|---|---|---|---|
| [AG Grid](https://www.ag-grid.com/) (Community) | טבלה | עמודות, עריכת תאים, בחירת שורות, מיון, RTL, גרירה ומתיחה של עמודות, שמירה ושחזור של מצב העמודות | לא שומרת ל-DB. הביטול המובנה עובד רק על המסך, ומתאפס בכל טעינת נתונים |
| [TanStack Query](https://tanstack.com/query) | סנכרון מול השרת | שמירה ברקע עם עדכון אופטימי, החזרה אחורה בשגיאה (rollback), טעינה מחדש, ריענון תקופתי, זיכרון בין מסכים | לא מזהה התנגשויות בין משתמשות ולא יודעת לבטל פעולות |

## מה נבנה בקוד, כי אין לזה ספרייה

- **ביטול שמגיע ל-DB:** הביטול שולח לשרת את הפעולה ההפוכה, כלומר פעולה מפצה.
- **זיהוי התנגשויות:** לכל שורה יש מספר גרסה. השרת חוסם עדכון של גרסה ישנה ומחזיר מי שינתה אותה.
- **מחיקה רכה:** השורה מסומנת בשדה `deleted_at` ולא נמחקת, וכך אפשר לבטל מחיקה.
- **יומן פעולות:** נרשם מי שינתה, מה השתנה ומתי.
- **שמירת הגדרות העמודות בשרת** לכל משתמשת בנפרד.
- **הרשמה והתחברות.**

## ממצאים עיקריים

1. **אין ספרייה אחת שעושה הכל.** ספריית הטבלה אחראית על התצוגה, וספריית הסנכרון אחראית על השמירה. כללים על הנתונים, כמו התנגשויות, הרשאות וכפילויות, נבנים תמיד בשרת.
2. **הביטול המובנה של ספריות טבלה לא מגיע ל-DB.** ב-AG Grid הוא גם מתאפס בכל ריענון. ביטול שמגיע ל-DB קיים רק בגרסאות בתשלום של ספריות אחרות (MUI X Premium, CoreUI).
3. **"סינכרוני מול א-סינכרוני" אינה בחירה של המשתמשת.** הגישה המקובלת היא שמירה א-סינכרונית עם עדכון אופטימי: השינוי מוצג מיד, והשמירה רצה ברקע.
4. **שמירה מיידית עדיפה כשכמה משתמשות עובדות יחד**, על פני שמירה מקומית עם כפתור "שמור".
5. **עדכון מיידי בין משתמשות** (במקום ריענון כל 10 שניות) דורש שכבה נוספת: Server-Sent Events, או מנועי סנכרון כמו TanStack DB + Electric או Zero.

## טכנולוגיות

React 19 · Vite · AG Grid 34 · TanStack Query 5 · React Router 7 · Node.js + Express · PostgreSQL ב-[Neon](https://neon.tech)

## מבנה הפרויקט

```
client/                 האתר (React)
  src/pages/            מסכים: טבלת עובדים, פרטי עובד, יומן פעולות, כניסה, הרשמה
  src/columns.jsx       הגדרת עמודות הטבלה (AG Grid)
  src/useUndoStack.js   מחסנית הביטול
  src/api.js            תקשורת עם השרת
server/                 השרת (Express)
  src/routes.js         כתובות ה-API
  src/employeesService.js  שמירה, בדיקת גרסאות, יומן פעולות
  src/auth.js           התחברות והרשמה
  db/schema.sql         מבנה הטבלאות
  scripts/              יצירת טבלאות ונתוני דמו, הצגת תוכן ה-DB
```

## הרצה

צריך Node.js בגרסה 18 ומעלה, ומסד נתונים Postgres. אפשר לפתוח אחד בחינם ב-[Neon](https://neon.tech).

### 1. הגדרת חיבור למסד הנתונים
```
cd server
copy .env.example .env
```
בקובץ `server/.env` מדביקים את מחרוזת החיבור ל-`DATABASE_URL`, ומשנים את `JWT_SECRET` למחרוזת אקראית.

### 2. יצירת הטבלאות ונתוני דמו (פעם אחת)
```
cd server
npm install
npm run db:init
```

### 3. הרצה (שני חלונות טרמינל)
```
cd server
npm run dev
```
```
cd client
npm install
npm run dev
```
פותחים את http://localhost:5173 ונרשמים, או נכנסים עם משתמשת דמו: `chani` / `chaya` / `sara`, סיסמה `1234`.

### צפייה בתוכן מסד הנתונים
```
cd server
npm run db:show
```
